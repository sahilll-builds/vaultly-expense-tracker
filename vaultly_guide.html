1 What Vaultly Actually Is (Audited from Code)

Vaultly is a privacy-first, client-side personal finance and financial intelligence Single Page Application (SPA) paired with an on-demand serverless conversational AI assistant.

The Problem It Solves: Most budgeting and finance apps require users to upload bank logins, credit card statements, and daily cash transactions to unknown third-party cloud databases. Vaultly eliminates that risk entirely: 100% of financial transactions, budgets, recurring obligations, and savings goals remain on the user's local machine in browser localStorage.

Core Capabilities Discovered in Code:

  • Personal Finance Management: Multi-currency transaction logging, categorized budgets, multi-tier savings goals, and recurring payment tracking.
  • Financial Intelligence Engines:
    • 4-Pillar Financial Health Score: Evaluates Savings Rate (30%), Budget Adherence (30%), Runway Days (25%), and Volatility (15%).
    • What-If Digital Twin: Simulates cashflow scenarios before users make discretionary purchases.
    • Anomaly Detection Engine: Flags statistical expense spikes compared against historical category averages.
    • Safe-to-Spend Runway: Computes true disposable capital after deducting fixed commitments.
  • Conversational AI Assistant: Seamlessly queries real financial context when finance topics are discussed, while remaining a versatile assistant for coding, writing, learning, and general problem-solving.

2 High-Level Architecture Diagram

Vaultly separates the privacy-safe user interface from cloud AI using an intelligent dual-tier architecture:

TIER 1: Client-Side Browser (100% Private)
• DOM Viewport (index.html): 7 view panels, modal dialogs, and SVG icons.
• Presentation Layer (style.css): Obsidian Glass monochrome design system.
• Application Controller (script.js): Central reactive state object.
• Persistence: localStorage (Key: vaultly_state_v2).
• Analytics: HTML5 Canvas via Chart.js v4.4.1.
TIER 2: Cloud Serverless (api/chat.js)
• Vercel Serverless Function: Secure Node.js proxy environment.
• In-Memory Rate Limiter: Prevents API flooding and token exhaustion.
• Google Gemini API: Primary fast conversational LLM.
• OpenAI API: Secondary fallback LLM.
• Deterministic Offline Engine: Instant rule-based answers when offline.
Data Flow: User Click ➔ script.js Controller ➔ LocalStorage ➔ Math Engines ➔ DOM Update ➔ Optional /api/chat Proxy

8 Lesson 1: The Entry Point (index.html & The Anatomy of a Single Page Application)

1. What Are We Learning & Why?
We are learning how a Single Page Application (SPA) displays 7 completely different screens (Overview, Transactions, Analytics, Budgets, Goals, AI, Settings) without ever reloading the browser page. In traditional websites, clicking a link forces the browser to destroy the page and fetch a new HTML file. In modern applications, we download one HTML file once, and use CSS and JavaScript to swap what the user sees instantly.

🎭 The Beginner Analogy: The Theatre Stage and Scenery Backdrops
Imagine sitting in a theatre watching a play:
• In a traditional website, when Scene 2 begins, the entire theatre building is demolished and rebuilt from scratch. It is slow and causes a jarring white flash.
• In a Single Page Application, the stage stays in place. Behind the curtain, all 7 backdrops (the Castle, the Market, the Forest) are already standing. When Scene 2 starts, the stage crew simply shines a spotlight on the Market and turns off the lights on the Castle.

In Vaultly, index.html is that single stage containing all 7 panels at once!

2. Real Code Excerpt from index.html:

<!-- THE NAVIGATION CONTROLS (The Light Switch) -->
<nav class="sidebar-nav">
  <button type="button" class="sidebar-nav-item active" data-view-target="overview">
    <span>Overview</span>
  </button>
  <button type="button" class="sidebar-nav-item" data-view-target="budgets">
    <span>Budgets</span>
  </button>
</nav>

<!-- THE VIEWPORT CONTAINER (The Stage) -->
<main class="dashboard-viewport" id="dashboard">
  <!-- Panel 1: Overview (Currently Spotlighted) -->
  <div class="view-panel active" id="viewOverview" data-view="overview">
    <h1>Your money, in focus.</h1>
  </div>

  <!-- Panel 2: Budgets (Currently in the Dark) -->
  <div class="view-panel" id="viewBudgets" data-view="budgets">
    <h2>Budget Allocations</h2>
  </div>
</main>

3. Step-by-Step Breakdown:

  • class="view-panel": In style.css, this class is defined with display: none;. By default, every panel is completely hidden from view.
  • class="view-panel active": In CSS, adding the .active selector overrides the display: .view-panel.active { display: block; }. This is the spotlight!
  • data-view-target="budgets": A custom HTML5 data attribute. It acts as an address tag on the button telling JavaScript: "When clicked, target the panel named 'budgets'".
  • data-view="budgets": The matching address tag on the panel element itself.

4. App Connection Flow (How HTML, CSS, and JS Collaborate):

Step 1 (User Action): The user clicks the navigation button with data-view-target="budgets".
Step 2 (JavaScript Event Listener): In script.js, an event listener catches the click and reads button.dataset.viewTarget.
Step 3 (DOM Class Manipulation): JS runs switchView('budgets'):
• It finds all elements with .view-panel and removes the active class (turning off all stage lights).
• It finds .view-panel[data-view="budgets"] and adds the active class (turning on the spotlight).
Step 4 (Instant CSS Rendering): The browser immediately reveals the Budgets screen in 0.0 milliseconds without a page refresh!

5. Practical JavaScript Implementation (from script.js):

function switchView(viewName) {
  // 1. Turn off spotlights on all panels
  document.querySelectorAll('.view-panel').forEach(panel => {
    panel.classList.remove('active');
  });

  // 2. Turn on spotlight for the matching target panel
  const targetPanel = document.querySelector(`.view-panel[data-view="${viewName}"]`);
  if (targetPanel) {
    targetPanel.classList.add('active');
  }

  // 3. Update the active highlight on the navigation buttons
  document.querySelectorAll('[data-view-target]').forEach(btn => {
    btn.classList.toggle('active', btn.dataset.viewTarget === viewName);
  });
}
